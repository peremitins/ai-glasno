# AGENTS.md

Правила для автоматизированных агентов разработки в проекте «Гласно».

## Язык и порядок работы

- Отвечай на русском языке; комментарии в коде и коммиты пиши на русском языке.
- Перед изменениями кратко опиши общий план по пунктам, затем приступай к работе.
- Работай автономно в пределах поставленной задачи: собери контекст, реализуй изменение, выполни релевантные проверки и сообщи фактический результат.
- Не запускай автоматически скиллы `brainstorming` и `writing-plans`; используй их только по явному запросу пользователя.
- Один законченный и проверяемый этап — один атомарный коммит. Не отправляй коммиты в удалённый репозиторий без явного запроса.

## Обязательный контекст задачи

- До любых изменений прочитай `AGENTS.md`, `CLAUDE.md` и [техническое задание](.docs/ТЕХНИЧЕСКОЕ_ЗАДАНИЕ.md).
- `.docs/ТЕХНИЧЕСКОЕ_ЗАДАНИЕ.md` — единственный источник плана React-версии: он определяет текущий этап, допустимый объём и критерии готовности.
- Для задач паритета JobAI изучай эталон только в ветке `develop` и только для чтения. Не изменяй исходный проект JobAI из работы над «Гласно».
- Не ставь в ТЗ галочки заранее. Отмечай только точный существующий пункт `[ ] → [x]` после успешных релевантных проверок; новые пункты сначала согласуй с пользователем и добавь как `[ ]`.

## Расходы на AI и служебная генерация

- Ключи AI-провайдеров, relay-секреты и платёжные секреты предназначены только для runtime-функций приложения, запускаемых пользователем.
- Не используй эти ключи для генерации, перевода, проверки, классификации, дедупликации или других служебных задач разработки.
- Служебные задачи выполняй средствами активной подписочной сессии Codex или Claude Code. Не создавай скрипты с OpenAI/Anthropic SDK и не запускай платные batch-запросы.
- Для ограниченных отчётных задач выбирай read-only инструменты и минимальный доступный effort. Перед чтением используй точный поиск по имени файла, символу или тексту; не загружай целые каталоги без необходимости.
- Перед автоматизацией через `codex exec` проверь `codex login status`: допустима авторизация `Logged in using ChatGPT`, без `CODEX_API_KEY`.

## Стек и интерфейс

- React 19 + TypeScript + Vite.
- Маршрутизация: React Router.
- Состояние: Redux Toolkit + React Redux; асинхронные данные и кэш — RTK Query.
- Формы: React Hook Form + Zod.
- Локализация: i18next + react-i18next; пользовательские строки не хардкодить в JSX после подключения словарей.
- UI: Tailwind CSS + shadcn/ui. Цвета — только через CSS-переменные и токены; не используй `dark:`-хаки.
- Тесты: Vitest + React Testing Library.
- Для данных до подключения API используй MSW и типизированные mock handlers.

Создавай адаптивные компоненты mobile-first. Код должен работать в современных Chrome, Firefox, Safari, Edge и Telegram WebApp. Перед браузерными API проверяй доступность через `typeof`; для критичных возможностей предусматривай fallback.

## Архитектура

```text
src/
  app/       # провайдеры, router, Redux store и глобальные стили
  pages/     # компоненты маршрутов
  widgets/   # композиции экранов
  features/  # пользовательские действия и сценарии
  entities/  # модели предметной области и их отображение
  shared/    # API, конфигурация, утилиты и UI-элементы
  mocks/     # MSW handlers и тестовые данные
  i18n/      # конфигурация и словари локализации
```

- Не делай сетевые запросы из компонентов: используй hooks RTK Query.
- В Redux store храни только клиентское синхронное состояние. Серверные данные не дублируй в slice.
- Сложную логику размещай в feature-слое, listener middleware или отдельных функциях; JSX оставляй декларативным.
- Внешние данные валидируй Zod-схемами на границе транспорта.
- Используй `async/await` с `try/catch`; независимые параллельные операции запускай через `Promise.all` или `Promise.allSettled`.

## Безопасность и Git

- Не добавляй в репозиторий `.env`, приватные ключи, токены, реальные персональные данные, `node_modules`, `dist` и временные файлы.
- Не выполняй `git push --force`, `git reset --hard`, `git clean -f` и рекурсивное удаление без явного запроса пользователя и точной проверки цели.
- Перед коммитом выполни минимум `git diff --check`; перед заявлением о готовности запусти релевантные `lint`, `test` или `build` и сообщи их фактический результат.

## Serena

Serena доступна через общий MCP-сервер `http://127.0.0.1:9121/mcp`. Перед семантической навигацией активируй проект и начни с symbol/reference-инструментов. Перед правкой Redux store, API-слоя, shared-утилиты или публичного типа сначала проверь references.

Результат symbol references не всегда полный: компоненты в JSX, динамические импорты и косвенное использование могут не определяться. Перед удалением, переименованием или выводом о неиспользуемом коде обязательно перепроверь имя текстовым поиском через `search_for_pattern` или `rg`.
